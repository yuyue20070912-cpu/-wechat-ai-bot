# 第三阶段：诊断、每日任务与间隔复习

## 功能边界

IELTS、CET-4、CET-6 各有 6 道不同的原创文字入门题（`entry-v1`），覆盖词汇、阅读、听力文本理解、写作判断、口语文字表达与翻译判断。IELTS 翻译/词汇和 CET 口语属于拓展基础观察，不冒充官方笔试分项。

免费提交后由服务器按固定答案判分，保存正确率、每题解析、薄弱项与当时的考试档案。界面明确注明这是六题小样本的本地诊断，不是付费 AI 判分、CEFR 认证、官方 IELTS band 或 CET 总分。文字题不评价发音、真实流利度与听辨能力。

如未来获准启用，可主动点击“可选 AI 解读”：AI 基于已保存的诊断快照与目标补充学习建议，不改写客观题正确率。AI 返回的内部参考指标不会放入诊断正确率、能力统计或错题判定。

## 默认不调用付费 AI

以下操作均不调用 AI、不消耗消息额度：诊断判分、生成/恢复每日计划、勾选任务、保存错题、导入旧错题、复习与数据中心读取。

付费诊断解读需要**同时**设置：

```text
LEARNING_AI_ENABLED=1
LEARNING_DIAGNOSTIC_AI_ENABLED=1
```

两者默认均关闭，页面不会自动触发付费调用。本次没有修改正式环境开关或调用真实付费 API。

可选解读复用第二阶段唯一的付费反馈路径：共享原消息/会员额度、用户/全站每日调用预算、每分钟提交限流、每用户最多一个 pending、45 秒网络超时、20000 字节应用输入上限、1600 输出 tokens、零自动重试和 `store=False`。
每份诊断的 AI 请求 ID 由用户和诊断 UUID 确定，不能通过换客户端 UUID 重复扣费。成功后直接恢复反馈；失败退消息额度但保留调用预算。同一份失败报告不会重试调用，仍可查看本地结果。用户如需再次诊断，可创建新的入门测试记录，但付费解读仍受共享预算限制。

## 每日计划与恢复

`daily-v1` 使用考试目标分数、自评水平、最近诊断薄弱项、最近 30 次已完成 AI 练习的低分技能（不含诊断 AI 解读）、到期复习数量安排任务。
基础阶段优先词汇/阅读，较高目标增加任务数量或训练时间；IELTS 与 CET 的进阶默认技能不同。缺少目标或诊断时使用明确的基础任务，不编造诊断结论。

用户主动生成当天计划；建议先保存目标并完成诊断。计划以**用户 + 考试 + UTC 日期**唯一保存。重复生成与并发请求返回相同快照，不重置任务。当天修改档案或完成新诊断不会覆盖今天的任务，新的依据用于下一天。

任务勾选写入 PostgreSQL，退出重新登录、换设备或刷新可恢复。勾选/撤销包含 `expected_version`，相同状态重试不累加版本，相互冲突的旧更新返回 409。完成状态属于用户自报，不是系统核验的训练完成或考试成绩。撤销后，任务完成数及依赖该完成状态的活动日会重新计算。

## 智能错题本

- 每次诊断的错误项目，随诊断结果在同一事务中自动保存；包含原答案、正确选项和**本地**解析。
- AI 练习参考分低于 70 的项目，随成功反馈在同一事务中保存为“待巩固”；保存原 AI 总结、改进与表达改写，不将 AI 低分声称为客观判错。
- 其他已完成练习可从历史手动加入。每个来源只保存一次，重复操作不覆盖原解析或复习进度。
- 升级前已有的低分练习可点击导入，每批最多 100 条；错题本分页每页 30 条。导入不触发 AI。
- 诊断 AI 解读不属于练习错题，不能被手动收藏或自动导入。
- 所有查询和更新都以 Session 用户为范围，客户端不能指定 user_id。

## 间隔复习规则（版本 1）

客观题重新选择答案，服务器自动比较正确选项；开放表达需重新作答并自评，界面明确标识自评，不调用 AI 判分。

| 表现 | 下次安排 |
| --- | --- |
| 客观题错误 / 自评仍未掌握 | 10 分钟后，连续掌握次数清零，难度系数降低 |
| 自评勉强回忆 | 至少 1 天，之后按原间隔 × 1.2，难度系数降低 |
| 客观题正确 / 自评基本掌握 | 第 1 次 1 天，第 2 次 3 天，之后按间隔 × 难度系数 |
| 自评轻松掌握 | 至少 3 天，按间隔 × 难度系数 × 1.3 向上取整 |

系数限制 1.3–3.0，间隔最多 365 天；连续掌握至少 3 次且间隔至少 7 天时显示“已巩固”，仍会安排到期复习。这是产品启发式规则，不宣称为标准 SM-2 或经校准的学习效果预测。
所有到期判断使用数据库时间；复习写入持有项目行锁，要求版本匹配。请求 UUID、原版本、答案及自评状态被保存，重复请求返回原结果，不再次推进间隔。并发使用相同 UUID 处理不同项目时，失败一方整笔回滚。

## 数据中心的统计口径

- 学习天数：诊断、完成练习、复习、仍标记完成的任务的不同 UTC 日期；不是登录天数。
- 完成任务：当前标记完成的任务数，跨天累计。
- 正确率：最近一次六题文字诊断的客观正确率；无数据时显示“待诊断”。
- 诊断变化：最近两次同版本测试的正确率百分点差；不足两次不计算。重复相同题目有记忆效应，不据此宣称完整能力提升。
- AI 能力观察：分别展示每技能训练次数、AI 参考均分及首次/最近变化，不与客观正确率混合，诊断 AI 解读不计入。
- 最近 28 天：活动日格子；客观诊断趋势最多 12 个点。总训练数与学习天数使用完整数据聚合，不截取最近 20 条练习历史。

## API

所有 API 要求原登录；学习响应继续 `no-store`。所有写请求要求 `X-Learning-CSRF`。格式错误 400、无权访问/不存在 404、版本/重复内容冲突 409、限流 429、数据库故障 503。

| 方法 | 路径（均以 `/api/learning/` 开始） | 用途 |
| --- | --- | --- |
| GET/POST | `diagnostics/<exam>` | 获取测试 / 提交全部六题 |
| GET | `diagnostic-results/<id>` | 恢复自己的诊断与可选 AI 状态 |
| POST | `diagnostic-results/<id>/ai` | 用户主动触发一次有预算的解读 |
| GET/POST | `plans/<exam>` | 读取 / 生成或恢复今日计划 |
| PUT | `tasks/<exam>/<date>/<task>` | 按版本勾选或撤销 |
| GET | `overview/<exam>` | 数据中心 |
| GET | `reviews/<exam>?offset=0` | 分页读取错题与到期状态 |
| POST | `reviews/<exam>/sync` | 分批导入既有低分练习 |
| POST | `reviews/save` | 收藏已完成的私有练习 |
| POST | `review-responses` | 幂等提交复习答案与表现 |

## 迁移与回退

`003_learning_personalization.sql` 仅创建独立的新表和索引，不 ALTER 聊天、会员、支付或既有学习表，不执行 DML 回填。原显式命令 `flask --app bot learning-migrate` 继续使用单事务、3 秒锁超时、30 秒语句超时及互斥锁。

第三阶段代码的反馈结算需要新错题表，因此未来获准上线时必须**先迁移、后上应用**。旧应用兼容新增表，可在迁移失败时继续运行；回退应用时保留学习数据。迁移若未成功就上新应用，学习写入会返回服务错误，不能通过自动请求路径补建表。完整执行与备份步骤见 [安全方案](learning-rollout-safety.md)。

测试增加从第二阶段升级保留旧练习和新任务状态、重复执行，以及第三阶段 SQL 失败时整体撤回新表且保留旧档案。所有迁移测试仅使用临时数据库。

## 验证与限制

保留原全部回归用例，并新增诊断三考试、权限/CSRF、去重、并发计划/任务/复习、实际退出登录恢复、复习间隔、自动/手动/批量错题、统计口径与付费 AI 双开关/退款/预算共享测试。
Chromium/WebKit 的手机、桌面、深色模式场景覆盖诊断、收藏、任务勾选恢复和客观错题复习；所有 AI 响应均模拟，不需要正式凭证。
真实模型的诊断解读质量以及 iPhone/macOS Safari 真机仍未验收。语音和完整模考不在本阶段。

本地完整结果：157 项 Python 测试通过（包括原有全部回归与 Chromium/WebKit 共 6 个场景），4 项 JavaScript 流式测试通过；两个学习 JS 文件的语法检查、Python compileall 和 `git diff --check` 通过。本地 WebKit 沿用第二阶段工作区依赖方式，CI 使用官方 `--with-deps` 安装。
