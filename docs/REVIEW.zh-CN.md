# fishyeah Chat 审查及第一批修复

日期：2026-10-17。基线：`ai-development` 的 `aad2235affa94b3534db2086df70c830ffbe56dd`，当时与 `main` 相同。没有合并其他功能分支。

## 项目与功能

已阅读该分支全部业务代码、内嵌 HTML/JavaScript、CSS、SVG、依赖和 README。根目录 PNG 是图标。项目为 Flask 单体，没有前端构建、ORM、后台任务或独立迁移框架；原仓库没有测试、CI 或 Render 配置。

| 模块 | 已有实现 | 限制 |
| --- | --- | --- |
| 注册 | 大陆手机号格式、唯一性、密码哈希、限流、自动登录 | 无短信归属验证，可能抢注号码；无找回密码 |
| 登录 | 签名 Cookie、7 天有效期、退出、修改密码 | 改密只清理当前会话，其他设备旧 Cookie 仍有效 |
| AI 聊天 | 登录校验、4000 字上限、Responses API、额度预留与失败退款 | 单轮问题，没有上下文、持久历史、流式输出或请求幂等 |
| 免费额度 | PostgreSQL 原子 upsert，每用户每 UTC 日 5 条 | 重置时间与中国本地午夜不同；多账号可绕过产品层限制 |
| 会员 | basic/pro、30 天周期额度、活跃订阅查询、原子扣减 | 多个有效订阅只选择结束最晚的一条，新购/续费可能遮蔽旧额度 |

| 审核 | 长令牌、待审核列表、订单行锁、唯一支付流水号、事务开通 | 无独立管理员账号、MFA、审核人/时间/原因审计字段；依赖人工对账 |
| 部署 | Flask、gunicorn、PostgreSQL、环境变量、存活检查 | 仓库不能证明 Render 实际分支、命令、备份或密钥配置 |

数据库表：`users`、`daily_message_usage`、`auth_rate_limits`、`subscriptions`、`membership_orders`。SQL 使用参数绑定，密码使用 Werkzeug 哈希；页面通过 `textContent` 渲染模型及用户文本。Cookie 原本已启用 HttpOnly、Secure、SameSite=Lax。原订单审核已具备事务、重复审批防护和流水号唯一约束，已保留并测试。

## 已修复

1. **输入崩溃**：统一拒绝非对象/畸形 JSON；校验订单 plan 类型，防止数组、字符串、数字或不可哈希值触发 500。非 ASCII 管理员令牌安全返回 403。
2. **并发重复订单**：原先只锁“已有订单”，首次下单时没有可锁行。现在先在原事务中锁稳定的用户行，再查待审核订单和创建，避免同一用户并发重复下单。没有新增约束或清理已有数据。
3. **跨 UTC 日退款**：预留返回数据库实际 usage_day，免费失败退款使用原日期；会员退款继续定位原订阅 ID，避免跨午夜退到新一天。
4. **无有效 AI 回复仍扣费**：空、空白或未完成响应会退款；缺少 API key 时不预留额度。SDK 超时 20 秒、关闭自动重试、输出上限 2048 token，使用上下文管理器关闭连接。模型配置不变。超时不能保证上游未计费，关闭重试减少重复请求。
5. **支付流水号边界**：审核时 trim 流水号，拒绝空白，防止首尾空格绕开唯一性。未修改套餐价格、收款码或支付开关。
6. **跨站与缓存**：写请求检查 Origin / Sec-Fetch-Site 并要求 JSON 对象；账号、订单及管理响应 no-store，统一 nosniff、禁止 iframe 和同源 Referrer 策略。Host 比较兼容 Render TLS 代理终止；没有信任任意转发头或开放 CORS。无 Origin 的服务端 JSON 调用仍可用。
7. **账号切换残留**：清空聊天、消息、付款和改密输入，关闭菜单；过期请求不能写入新账号页面，旧 AI 回复不会串入下一账号。发送期间禁用新对话。保留现有布局、主题、头像与手机样式。
8. **验证基础**：限制登录/旧密码长度，聊天增加客户端长度与无障碍名称，补充测试、文档和仅运行检查的 GitHub Actions。
