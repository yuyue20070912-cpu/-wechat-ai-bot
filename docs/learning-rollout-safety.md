# 学习模块数据库安全上线方案（仅方案，未执行正式操作）

本 PR 不合并、不部署、不访问正式数据库。以下步骤供未来获准上线时使用。

## 上线前与演练

1. 确认原有 users、subscriptions、daily_message_usage、auth_rate_limits 已存在，确认当前应用版本和数据库版本；学习迁移不再调用原项目 init_db，避免意外触碰聊天、会员或订单表。
2. 在隔离测试库演练：空的学习 schema、已执行 001 的 schema、重复运行、锁竞争超时、失败回滚、旧应用与新表共存。使用脱敏数据，禁止复制手机号、学习答案或支付信息到开发日志。
3. 由数据库负责人确认托管备份/PITR 可用，保存还原点和迁移前 schema，并在隔离库完成恢复验证。不要把带凭证的连接串写进终端历史、工单或 PR。
4. 审查 SQL：只创建新的 learning_* 表、索引和约束，无 DROP、TRUNCATE、ALTER 既有业务表。新增外键可能短暂取得被引用表的锁，因此仍需低峰窗口和锁超时，不能称为无锁迁移。

## 经批准后的执行顺序

1. 保持旧版本处理线上流量；AI 功能保持 `LEARNING_AI_ENABLED=0`。准备好负责执行和回退的人员。
2. 在短期迁移身份下对**经确认的目标环境**运行 `flask --app bot learning-migrate`，只允许一个执行器。
3. 命令对所有学习迁移使用单个事务、事务级 advisory lock、`lock_timeout=3s` 和 `statement_timeout=30s`。并发迁移、锁等待或 SQL 失败时整体回滚；先调查原因再重试，不提升超时强行抢锁。
4. 迁移后只读核查表结构、主键/外键、分数约束与 pending 唯一索引。重复执行命令应不更改既有记录。`IF NOT EXISTS` 不能修复结构漂移，发现现有表与 SQL 不一致时应停止并编写新迁移，不能直接覆盖。
5. 部署应用后仍关闭 AI，验证登录、聊天流、免费额度、会员余额、订单查看、学习档案 CRUD 的测试账号冒烟流程。应用身份只需学习表 DML 权限，DDL 权限留给迁移身份。
6. 未来获准灰度时，再设置小的 `LEARNING_GLOBAL_DAILY_CALLS` / `LEARNING_USER_DAILY_CALLS` 并开启 AI；设置 OpenAI 项目预算告警/支出限制，观察成功率、超时、pending 超过 5 分钟、退款和实际 token 使用。不要记录答案或完整 AI 响应。

## 回退与中断

- 首选先把 `LEARNING_AI_ENABLED` 设为 0，停止新增 AI 费用；读取题库、档案、历史仍可用。
- 迁移失败无需手工清理：事务会撤回本次学习 schema 改动。命令不会运行在 HTTP 请求路径。
- 应用回退时保留 learning_* 表和已保存数据，旧代码不依赖这些表，禁止用 DROP 或数据回滚撤销迁移。
- 若已有 AI 请求，先等待 45 秒上游超时及在途请求结束；5 分钟后在经授权环境执行 `flask --app bot learning-recover`，每批最多 100 条，可重复执行。对账后再决定是否回退应用。
- 学习请求失败退还原免费日期或原订阅的消息额度；调用预算不退还，因为失败调用也可能收费。不得通过手工减计数绕过费用上限。
- 数据损坏时由数据库负责人按既定恢复流程处理，不能直接把整个数据库回滚到旧时间点，否则会丢失聊天额度、订阅和支付订单的新记录。

## 本次验证边界

上述 SQL 及命令只对 pgserver 的临时数据库执行。CI、开发及浏览器测试无需正式凭证或真实 OpenAI 请求。真实备份恢复、生产权限与生产锁行为留待有权限的负责人批准后验证。
