# 邮箱绑定与密码找回

登录方式仍为手机号 + 密码。账号安全中新增「绑定找回密码邮箱」，进入独立 `/account/email` 页面。当前密码验证成功后向指定邮箱发送验证码；只有验证码通过才将邮箱标记为已验证。更换邮箱同样需要当前密码和新邮箱所有权验证，验证前保留原绑定。

找回密码在 `/forgot-password` 输入注册手机号，服务器只向该用户**已验证的绑定邮箱**发邮件；不接受用户指定找回邮箱。未注册、未绑定、未验证的账号均不能取得重置凭证。公开发送接口不返回邮箱地址或绑定状态；这些账号和正常账号收到相同状态码、文案与随机挑战结构。邮箱限流、SMTP错误或发送队列满也维持相同提示。配置完全缺失时，所有号码一致返回503。手机号/IP公开限流与账号是否存在无关。邮件异步发送，公开请求不等待SMTP，不把邮件服务响应时间直接暴露给调用方。

## 服务器环境变量

| 变量 | 说明 |
| --- | --- |
| `SMTP_HOST` | 邮箱服务商的SMTP主机名 |
| `SMTP_PORT` | SMTP端口，例如隐式TLS为465，STARTTLS为587；遵照服务商要求 |
| `SMTP_USERNAME` | SMTP登录用户名 |
| `SMTP_PASSWORD` | SMTP密码或服务商专用授权码，仅放在服务器环境变量中 |
| `SMTP_FROM_EMAIL` | 服务商允许发送的发件邮箱地址，不包含显示名称 |
| `SMTP_SECURITY` | `ssl`（默认，隐式TLS）或 `starttls`（先升级TLS再登录），禁止明文传输 |

继续使用现有 `SESSION_SECRET_KEY` 和 `DATABASE_URL`，不要为了此功能更换会话密钥。验证码摘要使用会话密钥进行HMAC-SHA256，防止数据库泄露后穷举6位码；挑战和重置凭证使用256位随机值、数据库只存SHA-256摘要。无须阿里云账号、API或SDK，也不新增Python第三方依赖。

密钥不得写进源码、前端、日志或提交的环境文件。SMTP账户需启用认证发送，并按服务商要求验证发件地址/域名和配置SPF/DKIM。代码强制校验证书的TLS连接；STARTTLS失败时不会退回明文认证。部署环境还需允许访问对应SMTP主机和端口；本PR不更改Render配置或生产网络。

## 安全与一致性

- 绑定/找回验证码均使用密码学随机生成的6位数字（支持前导0），5分钟有效；数据库只存绑定到用途、挑战、邮箱的密钥摘要。验证成功立即消费验证码，不能重复换取重置凭证或重复绑定。
- 手机号/IP限流存在PostgreSQL中，多进程共享。找回发送每手机号每60秒1次、每15分钟5次、每24小时10次；每IP每15分钟20次。绑定发送/验证按用户每15分钟5次、IP每15分钟20次限流。发送到同一邮箱另有跨绑定/找回共用的60秒1次和24小时10次上限。
- 两类挑战各最多尝试5次。即使重置15分钟限流窗口，仍不能继续尝试同一挑战。找回校验、密码重置分别按手机号每15分钟5次、IP每15分钟20次限流。沿用 `request.remote_addr`，不信任客户端伪造转发头；反向代理可能使多用户共享IP额度。
- 成功核验后签发5分钟有效的一次性重置凭证，仅在浏览器内存传递，不进入URL或本地存储。重发废弃旧挑战和重置凭证，密码或已验证邮箱发生变化也会废弃之前的证明。
- 行锁/事务将验证码消费、邮箱绑定，以及密码更新、会话版本递增、重置凭证消费分别原子提交，防止并发重放。新密码使用scrypt加盐哈希。密码重置后所有旧Cookie的后续请求失效，数据库不可用时拒绝验证；已开始执行的请求/流不会中途撤回。
- 新用户字段均为可空/默认值，不改变旧用户登录、会员、订单、用量和学习数据。旧Cookie缺少会话版本时按0验证。旧用户必须先登录并验证绑定邮箱；忘记密码又未绑定邮箱的用户无法通过此页面自行找回，系统不会允许输入任意邮箱绕过。
- 找回邮件使用进程内有界队列（2个发送线程，最多20个在途任务），只在内存短暂保留明文验证码；后台核对挑战仍有效且邮箱/密码版本未改变后发送。任务丢失、进程重启、队列满或SMTP失败均不会产生可用凭证，用户可按限流规则重试。没有新增部署服务、外部队列或定时任务。
- 绑定邮件在完成当前密码确认后同步发送，失败会明确提示，但不会更改已有邮箱。后台SMTP异常仅记录通用日志，不记录邮箱、邮件内容、密码或验证码。
- 页面支持iPhone安全区域和系统深浅色；独立邮箱页面不改动主聊天布局。接口仅接收JSON、不开放跨域；Cookie保留HttpOnly/Secure/SameSite=Lax，验证码/凭证接口禁缓存，独立页面设同源CSP、禁止嵌入、禁止Referrer。

## 数据库与验证

沿用现有初始化机制，向 `users` 追加会话版本、可空邮箱/验证时间及邮箱版本；新增 `account_email_challenges`、`email_password_recoveries`。DDL可重复执行，无删除/迁移用户数据。旧短信挑战表不再创建或读取，即使旧表残留也不能授权邮箱找回流程。过期一天以上的找回/绑定记录在请求找回时清理。

自动化测试使用真实临时PostgreSQL和SMTP替身，覆盖TLS/认证参数、绑定当前密码和邮箱所有权、统一响应、错误/过期/限流、并发重放、未绑定禁止找回、旧会话撤销、旧用户登录、会员/用量保留，以及iPhone/WebKit和桌面/Chromium深浅色完整流程。不发送真实邮件。

继续更新现有Draft PR #21，不合并、不部署正式版。当前环境无SMTP凭据，真实邮件投递需在配置好服务商后验证，不声称已完成真实投递联调。
