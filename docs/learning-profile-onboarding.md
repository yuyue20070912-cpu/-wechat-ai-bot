本次基于 main `fb8f137`，分支 `feature/learning-profile-onboarding`。不包含、覆盖或合并音频 Draft PR #16 的提交；音频文件、生成工具、播放逻辑与音频路由均保持 main 原样。聊天主界面、会员、支付和免费额度未修改。

## 进入与保存

页面先读取当前登录账户的考试目录与学习档案，读取完成前不显示总览，避免闪现错误目标。

- **首次/无完整档案**：进入「考试选择」。保留原有三张考试卡，以及同一套「目标分数」「当前水平」「保存学习档案」控件、全部四个水平选项、HTML 和服务端校验。IELTS 仍为 0.5–9、步长 0.5；CET-4/6 仍为 1–710、步长 1。点击卡片只编辑该考试的草稿，不进入总览，也不应用新目标。
- **成功保存**：继续使用原有 `PUT /api/learning/profiles/<exam>` 和字段 `target_score` / `current_level`。收到有效成功响应后应用目标，进入总览并通知原有学习模块。保存失败保留当前页面、分数与水平并显示错误。
- **已有完整档案**：每次加载默认进入总览，无须重选或重填；已有旧数据也适用。当前目标以账户中**最近成功保存的档案**为准，按已有 `updated_at` 排序。保存时锁定当前账户行，并取数据库实时时间与该账户最大时间加 1 微秒的较大值，确保连续或并发保存严格按提交顺序递增；时钟相同或回拨也不会选错。历史上已经同时间戳的旧档案无法还原当时的保存顺序，保留考试 ID 兜底；再次成功保存即可明确当前目标。GET profiles 增加 `active_exam_type` 元数据，不改原有 profiles 顺序，无需数据库迁移或新的偏好表。
- **修改目标**：在「考试选择」编辑和保存；只有保存成功才改变其他学习模块的当前目标。每个考试的历史档案和学习记录继续保留，不删除。刷新、重新登录、清空浏览器存储或新设备均从服务端恢复已保存目标。
- **未保存输入**：在页面内按考试保留草稿，切换卡片或菜单不丢失；草稿只保存在当前页面内存，不冒充已保存数据，不在 localStorage 中保存。刷新或切换登录会话后只恢复服务端已保存内容。
- **异常与并行操作**：档案读取失败显示重试，不误判为新用户。学习写入或 AI 处理中不切换目标；保存期间保留当前编辑视图，成功后等待现有模块完成写入再通知它们切换。若等待超时，从服务端重新载入已保存目标，不改动原有任务/模考写入逻辑。

进入时的旧链接/hash 不绕过首次档案设置，老用户新加载仍默认总览；进入后菜单内的正常 hash 导航继续可用。

## 账号隔离

数据查询和保存仍使用服务器登录态中的用户 ID，不接收客户端指定账户。保存前复核现有会话 CSRF token；其他标签页注销、重新登录或换账号导致会话变化时，重载页面，避免把上一账户草稿提交到新账户。页面重新获得焦点/变为可见时也检查会话。401 会隐藏私有学习视图、清除档案编辑状态并提示重新登录；重试需重新载入。已有的 Safari 页面缓存恢复刷新行为保留。

## 菜单与视觉

主要入口按「学习总览、考试选择、专项练习、模拟考试、智能错题本、学习记录」排列，之后保留实际需要的「我的学习任务、英语水平诊断、返回 fishyeah Chat」。没有重复的「考试与专项」混合入口。

考试选择视图仅包含考试卡和完整档案表单；专项练习视图仅包含原有专项功能，使用已保存的当前考试目标。模块 DOM 不因菜单切换被重建，未提交练习、诊断选项和模考状态继续保留。

每项菜单都保留文字，左侧使用统一 20px、1.75px stroke 的内联 SVG，间距 12px；无图标依赖、无彩色菜单图标。SVG 为 `aria-hidden=true` / `focusable=false`，文字是可访问标签；默认中性灰，选中为 `#173D80`，明暗模式各自有可读的浅色高亮底。保留现有字体、字号、深蓝按钮、彩色考试卡、safe-area、表单输入字号、触控大小、抽屉焦点循环和 Escape 关闭。

## PR #18：WebKit 请求生命周期修复

CI 中报错的 `/questions` 与 `/mocks` 列表都是二级启动读取：分别在练习概况和模考目录完成后发出。保存提示、总览出现或文档 load 都不代表这些读取已结束；立即刷新会让旧页面异步链与文档卸载重叠。原实现没有在 `pagehide` 取消读取，也没有阻止旧异步链继续发请求。服务端日志显示正常同源请求，并非应通过放宽 CORS、认证或测试断言解决的问题。

专项与模考现在追踪 GET 的 AbortController，在 `pagehide` 取消仍在进行的读取，并在请求前及解析响应后检查页面是否已离开，防止继续发出二级请求。已经提交的写入不加入离页取消集合；原有超时、草稿保存与恢复机制保留。模考到期回调返回历史刷新的 Promise，使真实失败进入原有错误处理。

新增 Chromium/WebKit 各两项真实 Flask/PostgreSQL 测试：用服务端事件门控制响应时序，覆盖读取未结束时刷新、离页取消上游读取且不发出下一批请求、新文档重新读取，以及活跃页面 503 提示和模考到期历史刷新失败。测试服务关闭时等待已释放的请求线程结束。离页取消回归在修复前两个浏览器均失败，修复后通过。原有全流程 `assert not errors` 保留，增加请求、响应、失败、导航及错误栈的时间线作为失败诊断，不过滤网络错误，不增加重试或固定等待。

修复后本地完整 pytest：**234 passed**；聊天流解析 **4 passed**；全部现有 JS 语法检查与 `git diff --check` 通过。未调用真实 AI 或收费 API。
